# 云盘签到助手

AstrBot 插件，在普通 QQ 私聊中查询云盘签到任务、预览计划，录入任务所需凭据，管理本人绑定。任务可以按 Cron 自动签到，也可以由用户在条件齐备时手动发起一次签到；两者共用同一串行队列。

## 功能

- 查询帮助、任务列表、任务详情和未来三次计划时间。
- 通过私聊向导逐个录入任务字段，凭据认证加密后保存。
- 查看本人任务 ID、凭据是否已配置、是否暂停、自动通知偏好、绑定的下次自动计划触发和最近一次签到状态。
- 管理本人绑定的暂停状态和自动通知偏好；删除绑定需在 60 秒内确认。
- 管理员准备锁定提交的离线制品：固定天翼脚本，或 `direct_env` 的通用 Python/Node 任务，制品缓存到 AstrBot 数据目录。
- 管理员按 run_id 取消排队中或运行中的签到；取消只记录请求，排队中的请求不会执行，已经开始的业务结果可能未知。
- 管理员停用当前任务：先持久化停用意图并为该任务排队或运行中的签到写入取消请求，再用 AstrBot 配置接口保存 `enabled=false`；保存未确认时，目标保持禁止执行。
- 管理员在普通私聊中受控重载本插件：旧实例的执行、配置写入和清理停止后再加载同一插件，排队请求按恢复规则继续，运行中的签到不会重跑。
- 全局与任务启用、Neo 就绪且制品齐备时，按 Cron 自动为已完成录入的用户发起签到；同一次计划的用户组成一段连续队列，与其他任务和手动请求共用同一执行队列。
- 齐备前置条件后，用 `/签到 立即 <任务ID>` 手动执行一次已准备的天翼或通用任务；请求按提交顺序排队，同一时间只运行一个。
- 签到结束后按来源和本人通知偏好私聊发送终态；通知发送失败或插件重载时不会重新执行签到。
- 通知偏好只影响自动结果：`开` 接收全部自动结果，`关` 只接收自动失败。手动终态始终发送；暂停本人的任务绑定会阻止该任务上的自动和手动签到。

## 环境要求

- AstrBot 4.29.4 或更新的 4.x 版本。
- Python 3.12 或更高版本。
- 通过 aiocqhttp 适配器接入的 OneBot v11 实现，例如 NapCat；消息上报格式使用 `array`。
- 当前为 v0.0.1 开发版本，尚未发布正式版本。

## 安装

本文对应 `dev/0.0.1` 开发分支，请按下面命令安装。

```bash
cd /path/to/AstrBot/data/plugins
git clone --branch dev/0.0.1 https://github.com/PRSSTRA/astrbot_plugin_cloud_drive_checkin.git astrbot_plugin_cloud_drive_checkin
```

然后在 AstrBot WebUI 的插件页确认插件已加载并打开。运行依赖在 `requirements.txt` 中声明；如果 AstrBot 没有自动安装，请在 AstrBot 实际使用的 Python 环境中安装。加载失败时查看日志，修复后重载插件。

录入凭据和签到执行前需要部署主密钥 `CLOUD_DRIVE_CHECKIN_MASTER_KEY`。没有主密钥时，帮助、任务查询、本人状态和绑定管理仍可使用，但录入和手动签到会被拒绝，自动计划在有符合条件用户时以配置错误结束；生成、设置和备份步骤见 [配置说明](docs/configuration.md)。

## 快速上手

1. 使用 AstrBot 管理员账号私聊机器人，或把普通用户 QQ 加入 `whitelist_qqs`。
2. 按 AstrBot 当前配置的唤醒前缀发送指令。默认前缀是 `/`，发送 `/签到` 或 `/签到 帮助`。
3. 回复会显示用法、角色、服务开关和状态存储状态。

要开始录入，发送 `/签到 录入 <任务ID>`，例如 `/签到 录入 tianyi_cloud`。已有任务包括配置禁用的任务都可以录入，录入本身不会执行任务。

要启用自动签到，先保持全局 `enabled` 关闭，完成以下准备，再把 `enabled` 打开并重载插件：

1. 为任务设置 `enabled=true` 和 Cron，并启用 Neo 连接。
2. 用 `/签到 管理 准备 <任务ID>` 准备与当前任务配置版本一致的制品。
3. 让参与自动签到的用户完成 `/签到 录入 <任务ID>`。
4. 打开全局 `enabled` 并重载插件，后续计划时间开始自动入队。

通用任务沿用同一顺序：先在 `tasks` 中配置 `direct_env` 字段、固定的 `script_url`、`source_commit`、`sha256` 和 `dependency_bundle`，保存后执行准备，再让参与用户录入。手动验证发送 `/签到 立即 <任务ID>`；自动执行在打开全局 `enabled` 并重载后从后续计划时间开始。

任务配置版本变化后要重新准备制品，否则该任务的自动计划在有符合条件用户时会以配置错误结束并发送失败通知。要手动执行签到，条件齐备后发送 `/签到 立即 tianyi_cloud`。前置条件、自动触发规则和排队规则见[自动签到](#自动签到)和[手动签到](#手动签到)。

## 指令

| 指令 | 作用 |
| --- | --- |
| `/签到`、`/签到 帮助` | 显示用法、当前角色、服务开关和状态存储状态。 |
| `/签到 任务 [任务ID]` | 不带 ID 时列出任务；带 ID 时显示字段要求、Cron、时区、未来三次计划时间和配置版本；停用保存未确认时显示禁止执行。 |
| `/签到 录入 <任务ID>` | 开始 5 分钟字段录入。 |
| `/签到 我的` | 显示本人全部绑定及管理状态，以及各绑定的下次自动计划触发；不可用时显示固定说明。 |
| `/签到 状态 [任务ID]` | 显示本人绑定状态、最近一次签到状态和下次自动计划触发；带 ID 时只看该任务。 |
| `/签到 立即 <任务ID>` | 提交一次本人在该任务上的手动签到；前置条件和排队规则见下文。 |
| `/签到 暂停 <任务ID>` | 暂停本人该任务绑定；不改变任务的配置启用状态。 |
| `/签到 恢复 <任务ID>` | 取消本人该任务的暂停标记。 |
| `/签到 通知 <任务ID> 开\|关` | 保存本人该任务的自动通知偏好。 |
| `/签到 删除 <任务ID>` | 发起本人该任务绑定的 60 秒删除确认，不立即删除。 |
| `/签到 删除 <任务ID> 确认` | 确认删除本人该任务的绑定和凭据密文。 |
| `/签到 删除 <任务ID> 取消` | 放弃本人该任务的删除确认，不修改绑定。 |
| `/签到 管理 准备 <任务ID>` | 管理员准备该任务的离线制品（固定天翼或通用 Python/Node）；不启用任务，也不执行签到。 |
| `/签到 管理 取消 <run_id>` | 管理员记录取消请求；排队或尚未发送业务请求的签到不会执行，已开始的业务结果可能未知。 |
| `/签到 管理 停用 <任务ID>` | 管理员写入停用意图和取消请求，并保存该任务 `enabled=false`；保存未确认时目标禁止执行。 |
| `/签到 管理 重载` | 管理员停止旧实例后加载同一插件，先回复已接受，结束时回复结果；排队请求按恢复规则继续，运行中的签到不会重跑。 |

`/签到 我的` 和 `/签到 状态` 显示本人任务 ID、凭据是否已配置、是否暂停、自动通知偏好、最近一次签到的 run_id、排队、运行或完成状态、业务结果和通知状态，不显示字段值、密文、来源会话或字段 ID 清单。通知状态为“按偏好静默”时，表示自动成功结果按当前偏好未发送。其他用户不能查询这些记录。

自动计划按本人绑定逐条显示。该绑定当前可参与自动触发，且调度器已登记与当前任务版本一致的有效计划时，显示下次计划触发时间和配置时区。这个时间只是调度器登记的计划时间，不是保证执行时间：请求仍要进入与其他任务和手动请求共用的串行队列，可能等待。绑定暂停、全局或任务配置禁用、停用保存待确认、凭据录入中、没有当前计划、计划过期待刷新、调度停止、调度未就绪或调度错误时，不显示时间，改为对应的固定说明。

## 管理员准备离线制品

准备指令只对 AstrBot 管理员和 `plugin_admin_qqs` 中的账号开放，在普通 QQ 私聊中使用，每次准备一个任务。例如发送 `/签到 管理 准备 tianyi_cloud`。

- 支持固定天翼任务和通用任务。通用任务使用 `direct_env`，运行时为 `python` 或 `node`，结果适配器为 `json_protocol` 或 `process_only`；移动任务尚未支持。Node 任务要求所选 Neo profile 的镜像中提供 Node。匹配条件和可自定义字段见 [配置说明](docs/configuration.md#管理员准备)。
- 通用任务的源码由 `script_url`、`source_commit`（40 位提交）和 `sha256` 锁定。`dependency_bundle` 必须显式写成 `none`，或写成字符串形式的 `{"format":"zip-v1","url":"...","sha256":"..."}`；源码和依赖是两条独立固定提交。Python 依赖须为可直接导入的纯 Python 模块或包，Node 依赖放在 `node_modules/` 下。依赖文件扩展名为原生库，或内容为 ELF、WASM、Mach-O、fat/universal、真实 PE 时会拒绝准备，即使改名为 `.bin`；普通 JSON、PEM 等辅助数据可以随包，展开后统一为 0600。这些检查是支持格式限制，不构成对脚本在 sandbox 内构造原生代码的阻止。
- 准备只下载并校验配置中锁定的来源：天翼从 PyPI 下载锁定 wheel；通用任务下载 GitHub 固定提交的源码，必要时再下载声明的依赖包，然后在本地生成制品。准备不执行下载内容，不在宿主机安装依赖。
- 制品按内容缓存在 AstrBot 数据目录，已发布引用的上限为 32 个文件、合计 32 MiB。单个制品不超过 1 MiB，依赖 zip 不超过 1 MiB、解压后合计不超过 8 MiB。依赖 zip 最多 4096 个成员（含目录项），实际依赖文件最多 4095 个；制品最多 4096 个文件，含 `task.py` 或 `task.js`。有效缓存命中时不再下载；任务配置版本或打包输入变化后，需要重新执行准备。
- 插件服务开关和任务 `enabled` 都不影响准备。准备不修改配置，不建立执行请求，也不读取凭据。
- 准备成功后，回复包含任务 ID、制品 SHA256 和字节大小。
- 准备失败时按回复提示处理：检查脚本、依赖、下载网络、任务配置或数据目录，状态存储未就绪或写入未确认时重载插件后重试。

缓存位置、准备记录和失败处理见 [配置说明](docs/configuration.md#管理员准备)。手动签到只使用与当前任务版本、打包输入一致的已准备制品；制品未准备或失效时会拒绝手动请求。执行阶段只读取缓存制品，不下载、不重新构建，也不在宿主机运行脚本。自动计划遇到未准备或已失效的制品时，有符合条件的用户会以配置错误结束并发送自动失败通知，不执行脚本。

## 管理员取消签到

`/签到 管理 取消 <run_id>` 只对 AstrBot 管理员和 `plugin_admin_qqs` 开放，仍须在普通 QQ 好友私聊中使用；群聊、临时会话、其他平台和管理员身份都不绕过这一限制。run_id 从入队回复或 `/签到 状态` 获取；取消他人运行时，由运行所属用户提供。

成功回复只表示取消请求已经持久化，不表示远端业务已经撤销。终态按现有通知规则处理，收件人是运行所属用户；管理员身份不会改变收件人，也不能通过 `/签到 状态` 查看他人的记录。

- 在发送业务请求前确认取消，会阻止后续执行；凭据尚未上传时也不会继续上传。此时不写入冷却或全局执行间隔，排队中的请求直接以取消结束。
- 业务请求可能已经发出时，取消会停止本地等待并执行资源清理；清理未确认时保留记录并阻断后续执行，业务结果可能记为 `unknown`。已经取得的可靠结果保持原值，只附加取消原因。
- 取消不修改任务配置、Cron、全局或任务启用状态，也不暂停、恢复或删除任何绑定；后续自动计划从新的计划时间继续。
- 同一 run_id 重复取消、已结束的运行和无法识别的 run_id 都不会重跑业务、改写终态或补发通知；只有首次写入生效。
- 取消只要求当前管理员权限有效、状态存储就绪且执行队列可用；全局服务开关、任务启用状态、Neo 连接、制品和任务目录中的业务配置都不参与这次检查。
- 状态写入未确认时，回复会说明取消写入未确认；不能据此判断取消成功或失败，插件暂停新的执行，恢复后由运行所属用户查询状态。

## 管理员停用任务

`/签到 管理 停用 <任务ID>` 只对 AstrBot 管理员和 `plugin_admin_qqs` 开放，仍须在普通 QQ 好友私聊中使用；群聊、临时会话、其他平台和管理员身份都不绕过这一限制。停用不要求全局 `enabled`、Neo 连接、已准备制品或本人绑定，但任务目录必须能通过当前校验。

- 成功回复表示停用意图和取消请求已写入状态存储，且配置保存已确认。目标任务的 `enabled` 保存为 `false`，随后清除停用意图；其他任务配置、绑定、凭据和已完成记录不变，目标运行按原终态规则通知。
- 同一笔状态写入会为该任务所有排队中或运行中的签到批次写入取消请求，处理规则与[管理员取消签到](#管理员取消签到)相同：尚未发送业务请求的批次不会执行；已经开始的业务结果可能未知，可靠结果保持原值并附加取消原因。其他任务和已结束记录不受影响。
- 停用意图保存在 `checkin_state` 现有的 `dedupe` 集合中，键为 `task_disable:<任务ID>`，快照 schema 版本仍为 3。它是配置保存前的临时操作记录，不新增集合或迁移，也不是第二个永久启用开关；长期启用状态仍只看任务配置的 `enabled`。
- 任务不在当前目录且没有待确认停用意图时返回未找到，不写入意图、不修改配置，也不取消任何运行。
- 状态写入未确认时不会开始配置保存，回复会说明写入未确认。配置保存失败、返回 `False` 或保存期间配置校验失败时，回复会说明停用意图已保存但配置未确认；目标保持禁止执行，之后可重试停用，或在修复配置后重载插件。清除意图时复查发现目标已重新启用，则保留意图并报告未确认；复查线性化点之后的配置保存属于后续显式修改。
- 插件重载时先恢复未完成的停用意图，再启动 Neo 执行、签到队列和自动调度；恢复仍失败会导致重载或启动失败，不会启动这些执行组件。关闭插件会等待已接受的配置保存和意图清理完成。
- 停用意图存在期间，`/签到 任务` 的列表和详情显示“停用保存待确认（禁止执行）”，该任务的手动请求和后续自动计划都不会入队。意图清除后，列表和详情按配置显示为配置禁用。

要重新启用，在 AstrBot WebUI 将任务 `enabled` 改回 `true` 并保存，再按正常的配置版本和准备规则确认制品；准备记录和缓存与当前版本、打包输入一致时直接复用，失效时才重新准备。停用不会删除准备记录或缓存，已取消的请求不会恢复或重跑。默认禁用的内置模板保持不变，停用不会删除模板。

## 管理员重载插件

`/签到 管理 重载` 只对 AstrBot 管理员和 `plugin_admin_qqs` 开放，仍须在普通 QQ 好友私聊中使用；群聊、临时会话、其他平台和管理员身份都不绕过这一限制。通过权限检查后，命令不接受其他参数，多带内容时返回用法。

- 重载只要求当前管理员权限有效且权限配置可解析，本插件实例已初始化、未停止。全局 `enabled`、任务目录校验结果、Neo 连接、已准备制品、本人绑定和状态写入是否已确认都不参与准入。
- 前置检查通过后先回复已接受，再在后台停止旧实例并加载同一插件；结束后单独回复结果。一次只处理一个重载请求，另一个请求在首个请求结束前会收到繁忙提示，不会重复终止或加载。
- 管理员身份和私聊事件在指令到达时检查一次，取得插件管理器锁后、开始停止前再检查一次。权限撤销后，已接受但尚未开始的请求不会终止实例。
- 旧实例先停止自动调度、签到队列、管理员配置保存、制品准备、Neo 执行器和通知服务，等待已接受的配置保存、运行资源清理与已到期通知投递结束。执行、配置写入和清理全部停止后，才解绑并加载同一插件；新实例必须处于激活状态、状态存储就绪并接管同一状态槽，否则按失败处理。
- 状态写入待确认时，关闭过程先按原快照重试。重试仍失败则停在解绑和加载前，旧实例保留注册记录，回复固定的未完成提示；修复后在 AstrBot 插件页重载。
- 解绑后加载返回失败或接管检查失败时，插件关闭本次重载已初始化的新实例，再报告未完成；即使该实例已不在管理器注册记录中，也不会留下其执行组件。
- 任务目录无效不会阻止受理，但新实例初始化会失败并返回未完成提示；旧实例此时已停止，先修复任务配置，再在插件页重载。
- 未过期且未开始的排队请求在加载后继续处理；已开始或结果不明的执行不会自动重跑，业务结果可能为 `unknown`，可靠结果保持原值。未结算通知继续投递，自动计划只从之后的计划时间开始。
- 重载不重启 AstrBot 宿主，不下载或安装插件代码、依赖更新，也不重载其他插件；其他插件的注册和运行不受影响。
- 发起指令的事件被取消时，只结束该次回复等待，不取消已接受的重载。AstrBot 退出或外部关闭插件会取消本插件拥有的重载任务，等待旧实例和本次重载已加载的新实例都关闭，再结束；关闭完成后不会由该任务重新加载插件，也不会留下新实例的执行组件。
- 当前实例已停止或未初始化，且没有正在处理的重载请求时，命令提示在 AstrBot 插件页重载，不重新启动旧实例。
- 框架重载接口或本插件注册状态不兼容时，命令在停止实例前固定拒绝；停止、解绑或加载过程中失败时返回固定的未完成提示。两种情况都要求在 AstrBot 插件页检查并重载，不会回退到其他重载调用。

重载按 AstrBot v4.29.4 的插件管理接口实现：通过公共 `Context` 查询当前插件元数据，使用受控的插件管理器锁和生命周期方法完成终止、解绑与加载。其他 4.x 版本接口不兼容时，前置检查会在停止实例前拒绝；重载过程中失败则返回未完成提示。依据见 [接口依据](CONTRIBUTING.md#接口依据与许可)。

## 自动签到

全局 `enabled` 和任务 `enabled` 都开启后，插件按任务 Cron 的到期时间自动为已完成录入的用户发起签到。Cron 按 `timezone` 计算，计划时间按 UTC 记录；同一任务同一计划只入队一次，插件重载、重复检查或时钟回拨都不会再次执行该计划。

- 启动、重载、重新打开全局开关或修改任务配置后，只从之后到达的计划时间开始。插件在 AstrBot 平台适配器加载完成后才建立未来计划基线；等待期间、停机期间和已经过去的计划不会补跑。运行中只处理当前到期分钟，跳过的旧计划不补跑。
- 运行期间持续检查当前到期分钟。每个到期计划先收集该任务上未暂停、且不在凭据录入向导中的本人绑定；权限已撤销、绑定缺失或已暂停的用户本次跳过。
- 符合条件的用户按身份稳定排序，作为一段连续队列入队，与手动请求和其他任务的请求共用同一串行 worker，没有额外 worker 或插队。
- 同一任务存在排队中、运行中，或已结束但仍在等待清理后结算冷却的批次时，本次自动计划整体记为跳过，不排队等待，也不部分执行；已经结束、仅等待发送通知的批次不阻断下一次计划，记录保留到通知结算后才能清理。
- 没有符合条件的用户时记为跳过，不创建请求，也不发送通知。
- 自动计划本身不检查手动冷却；未被手动加入的自动执行也不写入手动冷却，但实际执行与清理完成后会更新全局执行间隔。间隔值见 [配置说明](docs/configuration.md#执行设置)。
- 凭据缺失、Neo 暂不可用或制品摘要不匹配时，请求仍会进入队列并以配置错误结束，向用户发送自动失败通知；不会伪造摘要或改用其他脚本。

自动执行使用与手动签到相同的独立 Neo Sandbox、凭据解密和结果记录。到期任务准入时的已分类错误只记录在该任务下，其他到期任务继续；整份任务配置解析失败会暂停调度；未预期的内部错误会停止定时循环。这些错误都会通过 `/签到 我的` 和 `/签到 状态` 的 `last_error` 提示暴露；修复配置或重载插件后从后续计划继续。

自动终态通知按终态保存到 outbox 时的本人绑定偏好判断，保存后、发送前修改偏好不会重算已保存通知。`开` 接收全部结果；`关` 只接收失败、需要重新认证、结果未知或配置错误等非成功结果，成功或已签到的结果不发送通知，通知状态显示“按偏好静默”，且不尝试联网发送。若同一次执行中加入了本人的手动请求，则按手动终态强制发送一条通知。绑定在终态保存前被删除时按仅失败处理。

## 手动签到

发送 `/签到 立即 <任务ID>` 提交一次本人在该任务上的签到，例如 `/签到 立即 tianyi_cloud`。缺少任务 ID、参数过多或任务不存在时不会创建请求。

开始排队前须同时满足：

- 插件 `enabled` 和任务 `enabled` 都为真。
- Neo 连接已启用，启动恢复和访问检查通过，且没有待清理资源阻断执行。
- 任务的已准备制品与当前配置版本、打包输入一致。
- 本人已有该任务完整且未暂停的绑定，当前不在凭据录入向导中。
- 部署主密钥可用，用于解密本人凭据。
- 任务属于受支持且已准备的形态：固定天翼声明，或 `direct_env` 搭配 `json_protocol`、`process_only` 的通用 Python/Node 任务；移动任务不能执行。

请求入队后即持久化，回复包含 run_id。管理员可按该 run_id 取消请求，规则见[管理员取消签到](#管理员取消签到)。排队请求按提交顺序执行，同一时间只运行一个签到；自动计划生成的用户请求同样排在同一条队列中。

- 同一用户对同一任务的请求尚未结束时，重复提交返回原来的 run_id，不新建请求。若尚在运行的是该任务自动生成的请求，本次手动提交会加入原请求并标记手动参与，结束后强制发送手动终态通知。冷却未结束时不会创建请求；手动冷却按本人任务绑定计算，只在本人的手动参与实际执行后写入，未被手动加入的自动执行不写入手动冷却。
- 排队超过 `queue_expiry_seconds`（默认 900 秒）仍未开始，会记为取消并发送终态通知。
- 上一次实际执行与清理完成后，下一条若切换到不同任务，按 `task_interval` 默认等待 60 秒固定；若仍是同一任务但换成另一用户，按 `user_interval` 默认等待 30 到 60 秒随机。两者只参考最近一次全局完成记录，未实际执行的请求不改变起点。间隔值见 [配置说明](docs/configuration.md#执行设置)。
- 同一任务存在排队中、运行中，或已结束但仍在等待清理后结算冷却的批次时，新的自动计划整体跳过；已经结束、仅等待发送通知的批次不阻断。手动请求仍按本人绑定去重。
- 排队和运行期间持续检查权限、暂停状态、任务配置和制品摘要。撤权、暂停、删除绑定或任务变更会取消尚未发送的业务请求；存储未就绪时停止处理并按恢复规则保留记录。资源清理完成后才处理下一条。

执行时读取本人最新已确认的凭据，在独立 Neo Sandbox 中运行已准备的制品，不回退到宿主或 AstrBot 容器。业务结果与进程退出状态分开记录：天翼声明使用制品入口的 `tianyi` 结果；`json_protocol` 只从脚本输出的完整 JSON 对象读取已知业务状态，`process_only` 不读取业务结果；没有可靠证据时记为 `unknown`。

手动签到结束或取消后始终私聊发送终态通知，不受通知偏好影响；同一次执行中被手动加入的自动请求也按手动终态发送。通知包含任务、run_id、业务状态、原因、耗时和建议，不包含凭据或密文。发送失败会最多尝试发送 3 次；发送结果不明或插件在发送中退出时不会盲目重发，签到本身也不会因此重跑。`/签到 状态 [任务ID]` 只显示本人该绑定的自动计划信息和最近一条记录的 run_id、排队、运行或完成状态、业务状态和通知状态，不显示来源会话或凭据。

插件重载时保留未开始且未过期的排队请求，并继续处理未结算的通知；已经开始或结果不明的执行不会重放。自动计划不会补跑停机期间的计划，重载后从后续计划时间继续。

AstrBot 启动时，插件先等待框架完成平台适配器加载，再处理排队请求和待发送通知。尚未过期的排队请求保持排队，不会因为 QQ 适配器尚未出现在平台列表中而按撤权处理；插件启动恢复或关闭时，仍按入队时间把已过期请求记为取消。待发送通知在平台就绪后投递，等待期间不占用发送重试次数。平台就绪后恢复原有检查：权限撤销、绑定暂停或删除，或平台实例被实际移除，仍会取消尚未发送业务请求的签到。

## 凭据录入

- 录入限时 5 分钟，每条消息作为一个字段输入。只接受纯文本，图片、引用和文件会被拒绝。字符串按原文保存，不做裁剪；整数按十进制输入；布尔值输入 `true` 或 `false`，不区分大小写。执行时字符串原样传递，整数按十进制文本传递，布尔值统一为小写 `true` 或 `false`；用户字段与 `fixed_env` 合计最多 64 个变量，变量名和单个值不超过 16 KiB，值中不能含 NUL，序列化后的用户值与 `fixed_env` 值合计不超过 64 KiB。用户字段与 `fixed_env` 的变量名不能仅大小写不同地重名。
- 可选字段可以发送 `/跳过`，必填字段不能跳过。全部字段完成后发送 `/确认` 保存凭据；字段未完成时不会保存。
- 发送 `/取消` 放弃本次录入并清除未提交内容。
- 如果字段值正好是 `/取消`、`/确认`、`/跳过`，或以 `/值 ` 开头，发送 `/值 原文`。插件只去掉一次最前面的 `/值 `。
- 向导期间的消息不会交给 LLM。超时或插件重载后，未完成的录入仍会拦截你的后续私聊文本，避免密码误发给模型；发送 `/取消` 退出后，普通聊天才会恢复，然后再重新开始录入。
- 录入内容会作为 QQ 消息传输。QQ、OneBot 实现或框架的入站记录可能保留这些消息，插件无法清除。不能接受这一风险时，不要录入密码或令牌。

## 绑定管理

暂停、恢复、通知和删除只作用于本人绑定，不改变任务配置中的 `enabled`，也不影响其他用户。任务从任务目录移除后，原有绑定仍会保留，可以继续按任务 ID 管理或删除。

暂停和恢复修改本人绑定的暂停标记；暂停会取消本人在该任务上排队或尚未发送业务请求的手动签到，也会让本人在后续自动计划中被跳过。恢复后从后续计划时间重新参与。通知偏好按任务保存：`开` 表示接收全部自动结果通知，`关` 表示只接收自动失败通知。手动签到的终态通知始终发送，不受该偏好影响。

删除分两步：

1. 发送 `/签到 删除 <任务ID>` 发起确认。确认请求 60 秒内有效，只创建请求，不修改已保存的绑定。
2. 在 60 秒内发送 `/签到 删除 <任务ID> 确认` 删除该绑定及凭据密文。发送 `/签到 删除 <任务ID> 取消` 放弃请求，不修改绑定。

确认请求只对发起时的平台、QQ 和任务有效，且只能使用一次。请求只保存在运行内存中，插件重载后失效。超过 60 秒，或该绑定在确认前发生变化（例如重新录入凭据、修改暂停状态或通知偏好），原来的确认会失效，需要重新发起删除。

删除只移除插件保存的绑定和凭据密文，QQ、OneBot 实现或框架的入站记录以及管理员制作的备份需要单独清理。凭据录入向导尚未退出时，先发送 `/取消`，再执行绑定管理指令。

## 权限

只处理普通 QQ 好友私聊。群聊、临时会话、其他平台以及平台或 QQ 身份字段矛盾的事件会被静默忽略，管理员也不豁免。

| 身份 | 获得方式 | 可用指令 |
| --- | --- | --- |
| AstrBot 管理员 | 宿主框架管理员 | 全部查询、本人录入、本人手动签到、绑定管理、制品准备、取消运行、停用任务和重载插件 |
| 附加管理员 | 加入 `plugin_admin_qqs` | 全部查询、本人录入、本人手动签到、绑定管理、制品准备、取消运行、停用任务和重载插件 |
| 白名单用户 | 加入 `whitelist_qqs` | 全部查询、本人录入、本人手动签到和绑定管理 |
| 其他用户 | 无 | 收到无权提示 |

普通用户白名单为空时，所有非管理员用户都会被拒绝。管理员不需要加入白名单。权限配置在每条指令到达时重新读取，撤销后对后续指令立即生效；自动计划在准入和执行前也会复查权限。

## 配置

在 AstrBot WebUI 的插件配置页维护 `enabled`、`plugin_admin_qqs`、`whitelist_qqs`、`timezone`、`timeout_seconds`、`tasks` 和执行相关配置。`enabled` 关闭时仍可查询，手动签到会被拒绝，后续自动计划不再入队；管理员取消签到、停用任务和重载插件不受影响。

停用任务后，在 WebUI 把该任务的 `enabled` 改回 `true` 并保存，再按正常配置版本和准备规则确认制品；已有准备记录和缓存有效时可复用，失效时才重新准备。停用保存未确认时，`/签到 任务` 显示禁止执行，该任务的手动请求和后续自动计划都不会入队。

执行相关配置包括 `manual_cooldown_seconds`（默认 300 秒手动冷却）、`queue_expiry_seconds`（默认 900 秒排队有效期）、`history_retention_days`（默认 30 天历史保留）、`user_interval`（同任务换用户，默认 30 到 60 秒随机）和 `task_interval`（切换任务，默认 60 秒固定）。自动计划不检查手动冷却，未被手动加入的自动执行也不写入手动冷却；实际执行完成后会更新全局间隔。`user_interval` 和 `task_interval` 使用对象配置，支持固定、随机和关闭，`0` 表示无间隔；模式与字段规则见[配置说明](docs/configuration.md#执行设置)。

内置模板为 `tianyi_cloud`（天翼云盘）和 `mobile_cloud_experimental`（移动云盘，实验），默认禁用。模板只在未配置 `tasks` 时提供，显式设置 `tasks=[]` 不会补回。移动模板必须保持 `enabled=false` 和 `experimental=true`。

通用任务需要管理员在 `tasks` 中自行添加：`input_adapter` 为 `direct_env`，`runtime` 为 `python` 或 `node`，`result_adapter` 为 `json_protocol` 或 `process_only`，并用 `script_url`、`source_commit`、`sha256` 锁定源码。`dependency_bundle` 必须显式为 `none` 或 zip-v1 JSON；依赖包、字段和环境变量规则见[配置说明](docs/configuration.md#管理员准备)。

`neo_connection` 默认关闭。启用后，插件连接独立的 Docker Neo 服务并在启动时处理本插件遗留资源；不会自动部署 Neo。手动和自动签到都需要 Neo 连接和启动恢复就绪；尚未部署时保持关闭，查询、录入和绑定管理仍可使用。

完整配置表、任务字段、Cron、脚本来源、适配器和主密钥部署步骤见 [配置说明](docs/configuration.md)。

## 数据与安全

业务状态、签到队列、通知、自动计划记录和准备记录保存在 AstrBot 异步 KV 中，制品缓存在 AstrBot 数据目录。插件不创建数据库或业务状态文件，只支持单进程、单实例运行。

插件重载后会保留未过期的排队请求，并继续处理未结算的通知；已经开始或结果不明的执行不会重跑。自动计划不会补跑停机期间的计划。

从旧版本升级会保留已有绑定、加密凭据、排队记录、运行记录和通知；未开始的旧队列与旧通知会迁移为手动来源并继续处理。天翼任务需要重新执行准备才有可用制品，通用任务同样要先准备制品才能执行。

所有录入字段值都会认证加密后保存，主密钥与密文分开。插件只从环境变量读取主密钥，不生成、不打印；聊天回复不展示凭据值或密文。请保管原主密钥，不要直接更换；当前不提供自动密钥迁移，密钥丢失后需要重新录入。

存储写入未确认时，录入、绑定变更、删除、制品准备、签到入队、取消请求和停用任务都不会报告成功，正在等待确认的删除请求也会失效。取消请求在写入确认后才生效；停用任务只有在意图和取消标记写入确认后才开始保存配置。插件停止处理新的手动签到，自动调度暂停，已排队记录保留，不重放已开始的执行。恢复后自动计划从后续时间重新开始，不补跑阻塞期间的计划。请管理员恢复存储后查询本人状态；仍被录入向导拦截时发送 `/取消`。不要重复提交。
