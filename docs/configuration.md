# 配置说明

本文说明权限、主密钥、凭据录入、绑定管理、管理员准备、取消、停用与重载、自动与手动签到和任务目录。当前版本支持任务校验与预览、凭据录入、绑定管理、管理员准备、取消与停用、管理员重载、Cron 自动签到和手动签到。用户指令和快速上手见 [README](../README.md)。

## 权限设置

| 字段 | 默认值 | 规则 |
| --- | --- | --- |
| `enabled` | `false` | 服务开关；关闭时仍可查询，手动签到会被拒绝，后续自动计划不再入队；管理员取消签到、停用任务和重载插件不受影响 |
| `plugin_admin_qqs` | `[]` | 附加插件管理员 QQ；AstrBot 管理员默认拥有管理员权限 |
| `whitelist_qqs` | `[]` | 普通用户白名单；空列表不放行普通用户 |

QQ 号必须是正整数，或由数字组成、不含空白、符号和前导零的字符串。白名单为空时，所有非管理员用户都会被拒绝。管理员不需要加入白名单。

权限只在普通 QQ 好友私聊中生效。群聊、临时会话、其他平台以及平台或 QQ 身份字段矛盾的事件会被静默忽略，管理员也不豁免。权限配置在每条指令到达时重新读取；自动计划在准入和执行前也会重新检查，撤销后该用户本次跳过或取消尚未发送的业务请求。

`/签到 管理 取消 <run_id>` 只对 AstrBot 管理员和 `plugin_admin_qqs` 开放，同样只在普通 QQ 好友私聊中处理；普通用户白名单不授予取消权限。`/签到 管理 停用 <任务ID>` 使用相同的管理员范围和私聊限制，白名单不授予停用权限。

## 全局设置

| 字段 | 默认值 | 规则 |
| --- | --- | --- |
| `timezone` | `Asia/Shanghai` | IANA 时区名称，用于计算预览和自动计划时间；名称必须能被宿主的 `zoneinfo` 识别 |
| `timeout_seconds` | `180` | 全局任务超时，允许 1 到 240 秒；任务中的 `0` 表示继承此值 |
| `tasks` | 内置模板 | 任务数组；未设置时使用内置模板，显式设为 `[]` 时任务列表为空 |

任务目录最多 32 个任务。`tasks` 不是数组、任务不是对象、任务 ID 重复或任一任务校验失败时，整份任务目录被视为无效。加载阶段发现无效会导致插件加载失败；运行期间发现无效时，插件拒绝处理指令，自动计划暂停并记录调度错误；修复配置后从后续计划时间继续。

## 执行设置

签到执行读取以下顶层字段。字段缺失时使用默认值。顶层整数字段和间隔中当前模式使用的秒数字段不接受布尔值、负数或非整数。间隔必须是对象，键只能来自 `mode`、`seconds`、`min_seconds` 和 `max_seconds`；`fixed` 需要 `mode` 和 `seconds`，`random` 需要 `mode`、`min_seconds`、`max_seconds` 且下限不大于上限，`none` 只需要 `mode`。WebUI 可能保留其他模式的字段，解析时只使用当前模式需要的字段。

| 字段 | 默认值 | 规则 |
| --- | --- | --- |
| `manual_cooldown_seconds` | `300` | 同一用户在同一任务上的手动冷却秒数；从该绑定上一次手动参与的实际执行与清理完成时开始，`0` 表示不等待。自动计划不检查此项，未被手动加入的自动执行也不写入手动冷却 |
| `queue_expiry_seconds` | `900` | 从请求入队时开始计算；到期仍未开始则记为取消并发送终态通知，`0` 表示入队后立即到期 |
| `history_retention_days` | `30` | 已结算签到记录（批次、同 run_id 运行、通知和已结算的自动计划记录）的保留天数；`0` 表示下次清理时移除已结算记录，排队、运行、未结算通知和任务水位不受影响 |
| `user_interval` | `{"mode": "random", "min_seconds": 30, "max_seconds": 60}` | 同一任务换另一用户连续实际执行时的间隔 |
| `task_interval` | `{"mode": "fixed", "seconds": 60}` | 下一条切换到不同任务时的间隔，单独生效 |

`user_interval` 和 `task_interval` 支持以下模式，未生效字段可以保留但会被忽略：

```json
{"mode": "fixed", "seconds": 60}
{"mode": "random", "min_seconds": 30, "max_seconds": 60}
{"mode": "none"}
```

不接受单个整数、字符串或 `null` 作为间隔。固定和随机模式中的秒数可以是 `0`，表示不等待。两种间隔只参考最近一次全局实际执行与清理完成：下一条任务不同时使用 `task_interval`，且不叠加 `user_interval`；任务相同但用户不同时使用 `user_interval`；同一用户同一任务的手动请求还受 `manual_cooldown_seconds` 约束。自动计划只跳过手动冷却，仍会更新全局执行间隔。排队中、尚未发送业务请求就取消或未实际执行的请求不改变起点；发送业务请求后才取消的记录按实际执行更新。执行中的重复提交返回原 run_id，也不重置冷却。

活动排队最多 256 条，签到批次和通知各最多 1000 条。达到上限时插件拒绝新请求，不删除排队、运行或未结算通知记录来腾出空间；保留策略只清理已结束且通知已结算的记录。

签到执行只接受已启用、已准备，且属于受支持声明形态的任务：固定天翼声明（`tianyi_account` / `tianyi`），或 `direct_env` 搭配 `json_protocol`、`process_only` 的通用 Python/Node 任务。移动模板不能执行，即使已录入凭据。

## Neo 连接

尚未部署 Neo 时保持 `neo_connection.enabled=false`。查询、录入和绑定管理不需要 Neo，手动和自动签到需要。启用连接会初始化执行服务、恢复遗留资源清理，并在启动时完成访问检查。连接配置无效、鉴权失败或恢复记录不匹配会导致插件初始化失败；先修正配置，不要删除业务状态。

`neo_connection` 的字段如下：

| 字段 | 默认值 | 规则 |
| --- | --- | --- |
| `enabled` | `false` | 是否连接 Neo、在启动时恢复清理，并允许手动和自动签到 |
| `docker_cleanup_confirmed` | `false` | 管理员在目标部署独立验证 Cargo 物理删除后才能设为 `true`；仅确认 Docker 版本或 API 404 不足以放行 |
| `endpoint` | 空字符串 | 备用 Bay API 地址；必须明确填写 HTTP 或 HTTPS 地址，不含用户名、密码、查询参数或片段 |
| `profile` | `python-default` | 备用 profile，须提供 shell 和 filesystem 能力，镜像中须有 Python；Node 脚本还需要 Node |
| `access_key_env` | `CLOUD_DRIVE_CHECKIN_NEO_KEY` | 备用访问密钥的环境变量名，只填写名称，不填写密钥值 |
| `ttl` | `900` | 本插件沙箱 TTL，允许 300 到 3600 秒；不继承聊天沙箱 TTL |

启用后，插件通过 AstrBot 公共 `Context.get_config()` 读取 `provider_settings.sandbox`。当 `booter=shipyard_neo`，且 `shipyard_neo_endpoint`、`shipyard_neo_access_token` 均已明确配置时，优先使用这一完整连接和 `shipyard_neo_profile`。框架连接不完整、地址为空或为 `__auto__` 时，改用插件的完整备用连接，不把一个来源的地址与另一个来源的密钥拼在一起。插件不读取 Neo 的 `credentials.json`，不启动 Bay，也不获取聊天沙箱。

访问检查使用受保护的沙箱查询入口，查询一个不会由 Neo 自动生成的探测 ID：未带密钥须返回 401，带密钥须返回 Neo 的 `not_found`，随后读取公开 profile 目录确认目标能力。不会读取或借用聊天资源；匿名访问未关闭时拒绝执行。HTTP 仅用于可信的本机或隔离内部网络；跨不可信网络应使用 HTTPS。插件不自动修改服务鉴权、网络、权限或镜像。

### Docker 清理条件

Neo 提交 `f4d248b4274c1a2f05402f75a3b39e5c19be9ff5` 的 Docker bind 实现使用宿主绝对路径创建和删除 Cargo。如果该路径在 Bay 容器内指向另一处目录，就可能只删除容器层的空目录，而宿主 Cargo 数据仍在；此时 API 也会返回 `not_found`。因此不能仅凭该版本、Docker 类型或 API 404 认定物理清理成功。

使用 bind Cargo 时，宿主 Cargo 根目录必须以同一绝对路径挂入 Bay，并确认它与 Bay 配置中的 Cargo 根目录指向同一实际存储。保留原有挂载并增加同路径映射是已验收的一种做法。部署或升级后，先用独立假凭据 canary 验证 API 删除和宿主目录删除都成功，再设置 `docker_cleanup_confirmed=true`。命名卷模式也须独立验证，不能用 bind 模式结果代替；当前真实验收仅覆盖路径对齐后的 bind 模式。

资源创建至清理期间须保持同一 Docker daemon、存储配置和鉴权身份。不能凭 Cargo 的 `backend` 字段自动判断拓扑，该版本把它固定写为 `docker_volume`。插件不会自动更改挂载或重建 Bay；这些部署修改需要操作者授权。

每次执行都创建独立 Sandbox 和托管 Cargo。清理只使用本插件已经记录的资源 ID，检查 Cargo 的管理沙箱，删除 Sandbox 后再查询 Cargo；仍有残留时只重试该 Cargo 的删除，并要求查询返回 Neo 的 `not_found`。不会调用全局 GC、按创建时间猜测归属或删除聊天资源。这里验证的是资源删除，不是存储介质安全擦除，也不代表 Bay 历史记录已删除。

Kubernetes 不适用上述条件：PVC 删除受理后可能仍处于 Terminating，Cargo 记录却已经消失。该模式不能勾选 Docker 清理确认。

### 中断和清理失败

创建请求结果不明时不会重发创建请求；业务执行超时或断连也不会重发。资源 ID 不明、清理未确认或连接指纹变化时保留 `cleanup_jobs`，阻断新执行。连接指纹覆盖地址、密钥和 profile，不保存这些密钥的明文；存在待清理资源时不要切换连接，应先用原连接完成清理。

启动恢复只清理已记录资源，不补跑业务。仍处于初始接单阶段且没有资源 ID 的记录，可以确定尚未尝试分配并记为取消；已经提交创建意图的未完成记录按 `interrupted/unknown` 处理。创建结果不明且未取得资源 ID 时需要操作者核查，不能通过清空 KV 绕过。KV 写入未确认时仍遵守原快照重试规则，清理结果不能用来覆盖待确认写入。

本地取消不等于远端业务未发生。业务请求可能已经发出、但未收到有效结果时，终态为 `interrupted/unknown`；只有尚未发送业务请求，或 wrapper 明确返回取消结果时，才记录确定的业务取消。创建和执行意图的 KV 写入完成后，还会再次同步检查授权，避免写入等待期间撤权后继续执行。

已在路径对齐的 Docker Neo 上完成真实假凭据验收，范围和结果见 [贡献指南](../CONTRIBUTING.md#真实-neo-假凭据验收)。该验收的 Star/KV 边界为受控内存适配器，不代表真实 AstrBot/QQ 或真实账号签到已经通过；新部署仍须单独验证清理条件。

## 凭据主密钥

录入凭据和签到执行需要主密钥。帮助、任务查询、`/签到 我的`、`/签到 状态`，以及暂停、恢复、通知和删除等绑定管理操作都不读取主密钥。

| 项目 | 要求 |
| --- | --- |
| 环境变量 | `CLOUD_DRIVE_CHECKIN_MASTER_KEY` |
| 值 | 32 字节随机密钥的 URL-safe Base64 编码，按标准带填充 |
| 校验 | 必须能严格解码为 32 字节，重新编码后要与原值完全一致；其他长度或非规范 Base64 都视为无效 |
| 读取时机 | 每次开始录入或执行时从进程环境读取 |

Linux/macOS 可在可信终端执行下面的命令，将新密钥写入独立环境文件。命令不显示密钥，不覆盖已有文件：

```bash
python3 - <<'PY'
import base64
import os
from pathlib import Path

path = Path.home() / ".config" / "cloud-drive-checkin" / "master-key.env"
path.parent.mkdir(mode=0o700, parents=True, exist_ok=True)
fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, "w") as stream:
    key = base64.urlsafe_b64encode(os.urandom(32)).decode("ascii")
    stream.write("CLOUD_DRIVE_CHECKIN_MASTER_KEY=" + key + "\n")
print("已创建密钥文件：", path)
PY
```

通过现有服务管理器把这个文件中的环境变量注入 AstrBot 进程，例如 systemd 的 `EnvironmentFile` 或 Docker Compose 的 `env_file`。文件应与 AstrBot 数据备份分开保管，不能提交到仓库。需要重启才能更新进程环境时，由部署管理员确认并操作；插件不会修改服务配置或重启服务。

- 插件不生成、不打印主密钥，也不从插件配置读取密钥。
- 不要写进任务配置、`fixed_env`、QQ 消息、聊天记录、仓库或日志。
- 自行备份并保管原主密钥，不要直接更换。当前没有自动密钥迁移；丢失原密钥后，需要重新录入。
- 主密钥缺失或无效时，录入和手动签到返回固定提示并拒绝；自动计划在有符合条件用户时以配置错误结束并发送自动失败通知；查询和绑定管理继续可用。

## 凭据录入

- `/签到 录入 <任务ID>` 可以录入任意已配置任务，包括 `enabled=false` 的任务。录入本身不执行任务。
- 整段录入限时 5 分钟。每条消息作为一个字段输入，插件只接受全部由文本段组成的私聊消息；图片、引用、文件和其他非文本段会被拒绝。
- 字符串按原文保存，不裁剪空白、引号或换行。整数使用十进制写法，可以带正负号，不能包含空白。布尔值输入 `true` 或 `false`，不区分大小写。
- 必填字符串不能为空。含 NUL 的值会被拒绝。录入时字符串按 UTF-8 字节计算，单个用户值不超过 16 KiB；所有已录入值按执行时序列化后与 `fixed_env` 值合计不超过 64 KiB。
- 可选字段可以发送 `/跳过`，必填字段不能跳过。全部字段完成后发送 `/确认` 保存；未完成时发送 `/确认` 不会提交。
- 发送 `/取消` 放弃本次录入并清除未提交内容。
- 字段值正好是 `/取消`、`/确认`、`/跳过`，或以 `/值 ` 开头时，发送 `/值 原文`。插件只去掉一次最前面的 `/值 `。
- 超时或插件重载后，未完成录入仍会拦截该用户的后续私聊文本，避免内容交给 LLM；发送 `/取消` 后才能退出并恢复普通聊天。

`/签到 我的` 和 `/签到 状态 [任务ID]` 列出本人任务 ID、凭据是否已配置、是否暂停、自动通知偏好，以及最近一条签到的 run_id、排队、运行或完成状态、业务结果和通知状态。绑定当前可参与自动触发且调度器已登记与当前任务版本一致的有效计划时，还会显示该绑定的下次计划触发时间和配置时区；时间仅表示登记的计划，请求仍要排入共享队列，不保证实际执行时间。暂停、全局或任务禁用、停用保存待确认、录入中、计划缺失或过期、调度停止、未就绪或错误时显示对应的固定说明，不显示时间。通知状态为“按偏好静默”时，表示自动成功结果按当前偏好未发送。它们不显示字段值、密文、来源会话或字段 ID 清单。没有匹配绑定时返回“没有符合条件的本人绑定。”。

## 绑定管理

暂停、恢复、通知和删除只修改本人绑定，不改变任务的 `enabled`，也不影响其他用户。任务从任务目录移除后，原有绑定仍会保留，可以继续按任务 ID 管理或删除。

`/签到 暂停 <任务ID>` 和 `/签到 恢复 <任务ID>` 修改本人该任务的暂停标记。暂停会取消本人在该任务上排队或尚未发送业务请求的手动签到，也会让本人在后续自动计划中被跳过；恢复后从后续计划时间重新参与。`/签到 通知 <任务ID> 开|关` 保存自动通知偏好，`开` 表示希望接收全部自动结果通知，`关` 表示只接收自动失败通知；手动终态通知始终发送。新绑定默认未暂停，通知偏好为 `关`。

删除需要两步确认：

1. `/签到 删除 <任务ID>` 创建 60 秒有效的确认请求，只保存在运行内存中，不修改已保存的绑定。
2. 在 60 秒内发送 `/签到 删除 <任务ID> 确认`，才会删除该绑定和凭据密文。发送 `/签到 删除 <任务ID> 取消` 放弃请求，不修改绑定。

确认请求只对发起时的平台、QQ 和任务有效，只能使用一次，插件重载后失效。超过 60 秒，或该绑定在确认前发生变化（例如重新录入凭据、修改暂停状态或通知偏好），原来的确认会失效，需要重新发起。其他用户或其他绑定的变化不会使该确认失效。

删除只移除插件当前保存的绑定和凭据密文。QQ、OneBot 实现或框架的入站记录，以及管理员制作的备份，需要单独清理。任务的 `enabled` 和其他用户的绑定不受影响。

录入向导尚未退出时，先发送 `/取消`，再执行绑定管理指令。

## 手动签到

`/签到 立即 <任务ID>` 为提交者本人创建手动签到请求。缺少任务 ID 或带有额外参数时返回用法，未知任务返回未找到。权限、任务目录和存储无效时按查询指令的固定提示处理。

请求入队前同时检查以下条件，任一不满足都会拒绝且不创建请求：

- 全局 `enabled` 和任务 `enabled` 都为真。
- Neo 连接启用，启动恢复完成，访问检查通过，且没有待清理资源阻断执行。
- 任务的已准备制品与当前配置版本、打包输入指纹一致。
- 提交者已有该任务完整绑定、最新已确认凭据，绑定未暂停，且不在凭据录入向导中。
- 部署主密钥可用，用于解密本人凭据。
- 任务属于受支持的执行形态：已准备的天翼声明，或 `direct_env` 搭配 `json_protocol`、`process_only` 的通用 Python/Node 任务；移动模板不能执行。

接收后先持久化排队记录，再返回 run_id。同一用户在同一任务上的请求尚未结束时，重复提交返回原 run_id，不新建请求；若未结束的是该任务自动生成的请求，本次手动提交会加入原请求并标记手动参与，结束后发送手动终态。冷却未结束时拒绝，也不创建请求。冷却、用户间隔和任务间隔的默认值与计算方式见[执行设置](#执行设置)。

队列按提交顺序串行处理，同一时间只运行一个签到；自动计划生成的用户请求排在同一条队列中。执行只发生在独立 Neo Sandbox 中，不回退宿主或 AstrBot 容器。排队期间和运行期间会重新检查权限、任务配置、绑定状态和制品摘要；撤权、暂停、删除绑定或任务变化会取消尚未发送业务请求的签到，存储未就绪时停止处理并按恢复规则保留记录。业务请求可能已经发出时，终态记为 `interrupted/unknown`，不因本地取消而声称远端未执行。每个签到完成资源清理后才处理下一条。同一任务已有未结束批次时，新的自动计划整体跳过，手动请求仍按本人绑定去重。管理员可按 run_id 取消排队中或运行中的请求，阶段差异和通知对象见[管理员取消](#管理员取消)。

排队超过 `queue_expiry_seconds` 仍未开始时记为取消，并进入终态通知。已结束或取消的手动签到都会私聊发送终态，不受通知偏好影响；被手动加入的自动请求也按手动终态发送。通知只包含任务、run_id、业务状态、原因、耗时和建议等安全字段，不包含凭据或来源会话。发送失败最多尝试发送 3 次，通常在首次发送后 30 秒内结束；发送结果不明或插件在发送中退出时记为未知，不盲目重发，也不重跑签到。

`/签到 状态 [任务ID]` 只向绑定所有者显示该绑定的下次计划触发或固定不可用说明，以及最近一条记录的 run_id、排队、运行或完成状态、业务结果和通知状态。插件重载后保留未开始且未过期的排队请求，并继续处理未结算的通知；已经开始或结果不明的执行不会重放。

## 自动签到

全局 `enabled` 和任务 `enabled` 都开启后，插件按任务 Cron 的到期时间自动为已完成录入的用户发起签到。调度器按秒检查当前到期分钟，只有落在当前分钟的计划才入队；已经错过的旧计划不补跑。启动、重载、重新打开全局开关或任务配置版本变化后，只登记之后的计划时间，停机期间和已经过去的计划不会补跑。

每个到期计划按以下步骤处理：

1. 从任务绑定中收集未暂停、且不在凭据录入向导中的用户。权限已撤销、绑定缺失或暂停、录入未完成的用户本次跳过。
2. 按平台和 QQ 身份稳定排序，组成一段连续队列入队。请求与手动请求及其他任务的请求共用同一串行队列，不创建额外 worker，也不插队。
3. 同一任务存在排队中、运行中，或已结束但仍在等待清理后结算冷却的批次时，整次计划记为跳过，不创建请求，也不部分执行；已经结束、仅等待发送通知的批次不阻断下一次计划，记录保留到通知结算后才能清理。
4. 没有符合条件的用户时记为跳过，不创建请求，也不发送通知。

自动批次尚未结束时，同一用户发送 `/签到 立即 <任务ID>` 会加入对应的自动请求并复用 run_id，不新建批次；结束后按手动参与发送终态通知。

自动计划不检查 `manual_cooldown_seconds`，未被手动加入的自动执行也不写入手动冷却；但每条实际执行与清理完成后都会更新全局执行间隔。凭据缺失、Neo 暂不可用或制品未准备、摘要不匹配时，请求仍会进入队列并以配置错误结束，发送自动失败通知；不会伪造摘要或改用其他脚本。

计划时间按 `timezone` 计算，持久化时使用 UTC。同一任务同一计划时间只处理一次，插件重载、重复检查、时钟回拨或清理旧记录都不会让它再次执行；任务水位记录阻止被清理的旧时间重放。

`/签到 我的` 和 `/签到 状态` 只显示查询者本人绑定的下次计划触发和配置时区；该时间是调度器当前登记的计划，不是保证执行时间，请求仍可能因共享队列而等待。绑定不可参与自动触发、计划过期或调度未就绪时，对应位置显示固定说明。

自动终态通知在终态时确定：

- 手动发起或手动加入自动批次的记录始终发送。
- 自动结果中成功和已签到默认不发送；非成功结果（失败、需要重新认证、结果未知、配置错误等）发送。
- 终态保存到 outbox 时，本人该任务绑定的 `notify_all` 为 `true` 则全部自动结果发送；保存后、发送前修改偏好不会重算已保存通知。绑定在终态保存前被删除时按仅失败处理。
- 成功自动结果不发送时使用“按偏好静默”状态，不尝试联网，也不占用重试；发送失败、重试和送达未确认规则与手动通知相同。

自动执行使用相同的独立 Neo Sandbox、最新已确认凭据和结果记录。到期任务准入时的已分类错误只记录在该任务下，其他到期任务继续；整份任务配置解析失败会暂停调度；未预期的内部错误会停止定时循环。这些错误都会通过 `/签到 我的` 和 `/签到 状态` 的 `last_error` 提示暴露；修复配置或重载插件后从后续计划继续。

推荐的启用顺序：

1. 保持全局 `enabled=false`，配置任务 `enabled=true`、Cron 和 Neo 连接。
2. 按当前任务版本准备制品。
3. 让参与用户完成凭据录入。
4. 打开全局 `enabled` 并重载插件。已有绑定从后续计划时间参与。

任务配置版本变化后，旧制品不再匹配，需要重新准备；调度从新版本之后的计划时间重新开始。

## 存储写入未确认

写入异常、超时或取消时，插件保留待确认快照并停止新的状态修改。录入、绑定变更、删除、制品准备、签到入队、取消请求和停用任务都不会报告成功；已发起的删除确认在尝试提交后失效。取消请求只有在写入确认后才生效；停用任务只有在停用意图和取消标记写入确认后才开始保存配置。手动签到停止处理新记录，自动调度暂停，已排队记录保留；待确认写入只按原快照重试，不用新记录覆盖，也不重放已开始的执行。恢复后自动计划从后续时间重新开始，不补跑阻塞期间的计划。此时不要重复提交，也不要手工修改 KV 或缓存文件。

状态写入未确认时，管理员仍可发起 `/签到 管理 重载`；关闭旧实例时会先按原快照重试待确认写入，重试失败则停在解绑前并提示在插件页处理。重载不会补跑已开始的执行，重试失败后仍需先恢复存储。

管理员恢复存储后，先查询 `/签到 状态` 或重新执行所需操作。录入向导仍拦截私聊文本时，发送 `/取消` 退出。

## 管理员准备

准备在普通 QQ 私聊中由 AstrBot 管理员或 `plugin_admin_qqs` 成员执行，普通用户白名单不授予准备权限。例如：

```text
/签到 管理 准备 tianyi_cloud
```

固定天翼声明：与仓库固定天翼执行声明逐项一致的任务。可以自定义任务 ID、名称、Cron、启用状态、超时和实验标记；以下字段必须与仓库天翼默认声明一致：`runtime` 为 `python`，`script_url`、`source_commit`、`sha256` 为固定值，`input_adapter` 为 `tianyi_account`，`result_adapter` 为 `tianyi`，`dependency_bundle` 和 `fixed_env` 为空，`user_fields` 的顺序、数量及每项的 `field_id`、`label`、`env_name`、`value_type`、`required`、`secret`、`hint` 完全相同（当前为 `username`、`password`）。任一不一致都会拒绝准备。

通用任务：`input_adapter` 为 `direct_env`，`runtime` 为 `python` 或 `node`，`result_adapter` 为 `json_protocol` 或 `process_only`。移动任务尚未支持。源码和依赖都由任务配置锁定：

- `script_url` 与 `source_commit`：固定 40 位提交的 HTTPS GitHub 地址，`sha256` 是源码内容的 SHA256。URL 规则与[脚本来源](#脚本来源)相同。
- `dependency_bundle`：必须显式填写字符串 `none`，或填写下面这段 JSON 文本。插件不会把空字符串当作无依赖。

```json
{"format":"zip-v1","url":"https://raw.githubusercontent.com/<owner>/<repo>/<40位提交>/<路径>","sha256":"<64位小写十六进制>"}
```

`url` 使用固定 40 位提交的 HTTPS GitHub 地址，地址规则与 `script_url` 相同；`sha256` 锁定依赖 zip 的内容。插件把它规范化为 `raw.githubusercontent.com` 形式，只接受 `format`、`url`、`sha256` 三个键且 `format` 必须为 `zip-v1`，并会以规范化结果参与配置版本计算。源码和依赖是两条独立锁定，可以来自不同仓库或不同提交。

准备只从 `raw.githubusercontent.com` 下载这两个地址，校验 SHA256 后在本地打包；不执行下载内容，不在宿主机安装依赖，也不运行包管理器。

依赖为 `none` 时，制品就是源码文件本身（`script.py` 或 `script.js`），执行时直接上传源码。依赖为 zip-v1 时，制品是 zip：`task.py`（Python）或 `task.js`（Node）位于根目录，依赖文件按原路径加入。Python 依赖必须是能从制品根目录直接导入的纯 Python 模块或包；Node 依赖放在 `node_modules/` 下供 `require` 解析。

依赖包中的符号链接、加密成员、绝对路径、路径穿越、重复或仅大小写不同的路径、保留顶层名称，以及 `.so`、`.pyd`、`.dll`、`.dylib`、`.node` 扩展名都会被拒绝。准备和运行时还会检查文件内容：ELF、WASM、Mach-O、fat/universal 或真实 PE 文件头会被拒绝，即使文件改名为 `.bin`。普通 JSON、PEM 和其他非原生二进制辅助数据可以随包分发。包内权限位不保留，展开时统一为 0600 文件，运行时目录为 0700。

这些检查是准备和运行时的支持格式限制，不构成对受信管理员脚本在 sandbox 内自行编码或构造原生代码的阻止。

源码不超过 1 MiB，依赖 zip 不超过 1 MiB，生成的制品不超过 1 MiB；依赖 zip 最多 4096 个成员，单成员不超过 2 MiB，解压后合计不超过 8 MiB。

- 插件服务开关和任务 `enabled` 都不影响准备，默认禁用的模板也可以准备。准备只生成并缓存制品，不修改任务配置，不创建执行请求，也不读取凭据。
- 首次构建或缓存失效时需要网络。天翼任务异步读取 PyPI 的版本元数据，只从 `files.pythonhosted.org` 下载 `third_party/tianyi/requirements.lock` 锁定的 wheel，校验版本和 SHA256 后在本地生成 zipapp；通用任务从 `raw.githubusercontent.com` 下载锁定的源码，按声明再下载依赖包，校验后在本地生成源码或 zip 制品。
- 制品按内容缓存在 AstrBot 插件数据目录的 `prepared_artifacts/<制品sha256>.pyz`。数据目录为 `data/plugin_data/astrbot_plugin_cloud_drive_checkin`，由 `StarTools.get_data_dir()` 创建。准备完成后会清理未被准备记录引用的制品。已发布引用集合去重后的上限为 32 个文件、合计 32 MiB；超出时准备失败，配额不包含目录中的临时副本或其他文件。
- 准备成功后返回任务 ID、制品 SHA256 和字节大小。
- 准备记录保存在 `checkin_state` 快照的 `prepared_artifacts[task_id]` 中，包含任务配置版本、源码 commit 与摘要、制品摘要与大小、打包输入指纹。
- 任务配置版本、打包输入指纹和缓存文件摘要都与记录一致时，准备直接使用缓存，不再下载。任务配置版本或打包输入（源码、入口、运行时、依赖声明或依赖锁、许可）变化后，旧缓存不再命中，需要再次执行准备；插件不会在后台更新制品。
- 同一时间只处理一个准备请求，并发请求会收到繁忙提示，稍后重试。下载、校验或状态写入失败时，本次准备不报告成功。权限或任务配置在准备期间变化时，重新发起准备。状态存储未就绪或写入未确认时，按回复提示在插件页重载后重试；不要手工修改缓存或 KV。缓存文件缺失或被改动时，再次准备会按失效处理并重建。

准备不启用任务，也不加入执行队列。手动签到只使用已准备且与当前任务版本、打包输入指纹一致的制品；未准备、缓存失效或记录不匹配时拒绝请求。执行阶段只读取缓存中的制品，不下载、不重新构建，也不在宿主机运行脚本。自动计划遇到同样情况时以配置错误结束并发送自动失败通知。任务配置版本变化后需要重新准备，再等待后续自动计划。

## 管理员取消

```text
/签到 管理 取消 <run_id>
```

取消在普通 QQ 私聊中由 AstrBot 管理员或 `plugin_admin_qqs` 成员执行，普通用户白名单不授予该权限。run_id 来自 `/签到 立即` 的入队回复，或 `/签到 状态` 的最近记录；取消他人运行时，由运行所属用户提供。缺少参数、多带参数或 run_id 不是 32 位小写十六进制时返回用法或未找到，不修改状态。

成功回复只表示取消请求已经写入状态存储，不保证远端业务已经撤销。终态按现有通知规则处理，收件人是运行所属用户，管理员身份不改变收件人；其他用户的记录仍不能通过查询指令读取。

取消只要求当前管理员权限有效、状态存储就绪且执行队列可用。全局 `enabled`、任务 `enabled`、Neo 连接、制品和任务目录中的业务配置都不参与这次检查；服务开关关闭或任务目录无效时，仍可取消。

- 在发送业务请求前确认取消，会以 `cancelled` 结束，不执行脚本，也不写入冷却或全局执行间隔；凭据尚未上传时不会继续上传。
- 业务请求可能已经发出时，取消会停止本地等待并执行资源清理；清理未确认时保留记录并阻断后续执行，业务结果可能记为 `unknown`。已有可靠结果保持原值，只附加取消原因。
- 取消不修改任务配置、Cron、启用状态或任何绑定，也不取消后续自动计划；后续计划按正常规则从新的计划时间开始。
- 同一 run_id 重复取消、已结束的运行和不存在的 run_id 都不会重跑业务、改写终态或补发通知。
- 状态写入未确认时，回复会说明取消写入未确认；不能据此判断取消成功或失败，插件暂停新的执行，恢复后由运行所属用户查询状态。

## 管理员停用

```text
/签到 管理 停用 <任务ID>
```

停用在普通 QQ 私聊中由 AstrBot 管理员或 `plugin_admin_qqs` 成员执行，普通用户白名单不授予该权限。停用不要求全局 `enabled`、Neo 连接、已准备制品或绑定，但任务目录必须通过当前校验。命令只有在当前管理员权限有效、状态存储就绪、配置保存已确认并清除自己的停用意图后才报告成功。

- 任务存在于当前目录时，插件先在 `checkin_state` 的 `dedupe` 集合写入 `task_disable:<task_id>` 意图记录，并在同一笔状态写入中为该任务所有 `queued` 或 `running` 的签到批次写入取消请求。其他任务配置、绑定、凭据和已完成记录不变；目标运行按原终态规则通知。
- 状态写入确认后，插件重新读取最新配置，只把目标任务的 `enabled` 设为 `false`，通过 AstrBot v4.29.4 的公共异步配置保存方法 `save_config_async` 保存 `tasks`；其他任务字段、`__template_key` 和其他配置值保留。保存返回 `True` 后，插件在删除意图的同一次状态提交中再次确认最新配置仍禁用或已移除目标，才删除自己的意图记录；若复查发现目标已重新启用，则保留意图并报告未确认，复查线性化点之后的配置保存属于后续显式修改。方法签名和实现见 [astrbot_config.py](https://github.com/AstrBotDevs/AstrBot/blob/v4.29.4/astrbot/core/config/astrbot_config.py)。
- 停用意图是配置保存前的暂态操作记录，不改变快照 schema 版本 3，也不新增集合或迁移。任务的长期启用状态只由配置中的 `enabled` 表示，不存在第二个永久启用标记。
- 任务不在当前目录且没有待确认意图时，命令返回未找到，不写入状态、不保存配置，也不取消运行。保存期间任务从目录移除时，插件通过同一公共保存接口确认当前配置，保存确认后清除意图，不会重放旧配置。
- 写入配置前的状态提交未确认时，命令不会开始配置保存，回复说明写入未确认。停用意图写入后，配置校验异常、保存异常、保存返回 `False` 或保存后最新配置未体现停用时，回复说明停用意图已保存但配置保存未确认，目标继续保持禁止执行。此时可重试停用，或修复配置后重载插件；重复停用会再次尝试保存。
- 插件启动和重载会在 Neo 执行器、签到队列和自动调度之前恢复所有待确认意图，并按最新配置重试保存。恢复失败会导致初始化失败，不启动这些执行组件；修复配置后重载。关闭插件时会停止接受新的停用操作，等待已接受的配置保存和意图清理结束，再关闭状态存储。
- `/签到 任务` 的列表和详情在停用意图存在时显示“停用保存待确认（禁止执行）”，该任务的手动请求和后续自动计划在此状态下一律拒绝；意图清除后按配置显示为配置禁用。

重新启用时，在 AstrBot WebUI 把目标任务 `enabled` 改为 `true` 并保存，然后按正常的配置版本和准备规则确认制品；已有准备记录和缓存与当前版本、打包输入一致时直接复用，失效时才重新准备。停用不会删除准备记录或缓存，停用前已取消的请求不会恢复。内置模板默认禁用这一默认值不因停用改变，停用也不会删除模板。

## 管理员重载

```text
/签到 管理 重载
```

重载在普通 QQ 私聊中由 AstrBot 管理员或 `plugin_admin_qqs` 成员执行，普通用户白名单不授予该权限。通过权限检查后，命令不接受任务 ID 或其他参数，多带内容时返回用法；群聊、临时会话、其他平台和管理员身份都不绕过私聊限制。

- 重载只要求当前管理员权限有效且权限配置可解析，本插件实例已初始化、未停止。全局 `enabled`、任务目录校验结果、Neo 连接、已准备制品、本人绑定和状态写入是否已确认都不参与准入。
- 前置检查通过后，命令先回复已接受，再在后台停止旧实例并加载同一 `module_path`，结束后单独回复结果。同一状态槽同一时间只处理一个重载任务，重叠请求收到繁忙提示，不重复终止或加载。
- 当前管理员身份和私聊事件在指令到达时检查一次，在取得插件管理器锁后、开始停止前再检查一次。权限撤销后，已接受但尚未开始的请求不会终止实例。
- 停止阶段关闭自动调度、签到队列、管理员配置保存、制品准备、Neo 执行器和通知服务，等待已接受的配置保存、运行资源清理与已到期通知投递结束。旧实例的执行、配置写入和清理全部停止后，才解绑并加载；新实例必须已激活、状态存储就绪并接管同一 Context 状态槽，否则按失败处理。
- 状态写入待确认时，关闭过程先按原快照重试。重试仍失败则停在解绑和加载前，旧实例保留注册记录，回复固定的未完成提示；修复后在 AstrBot 插件页重载。
- 解绑后加载返回失败或接管检查失败时，重载任务关闭本次加载的精确新实例，再报告未完成；即使管理器已删除该实例的元数据，也不会留下其执行组件，也不会关闭其他重载或插件创建的实例。
- 任务目录无效不会阻止受理，但新实例初始化会失败并返回未完成提示；旧实例此时已停止，需要先修复任务配置，再在 AstrBot 插件页重载。
- 未过期且未开始的排队请求由新实例继续处理；已开始或结果不明的执行不会自动重放，业务结果可能为 `unknown`，可靠结果保持原值。未结算通知继续投递，自动计划只从之后的计划时间开始。
- 重载不重启 AstrBot 宿主，不下载或安装插件代码、依赖更新，也不重载其他插件；其他插件的注册和运行不受影响。
- 发起指令的事件被取消时，只结束该次回复等待，不取消已接受的重载。AstrBot 退出或外部关闭插件会取消本插件拥有的重载任务，等待旧实例和本次重载已加载的新实例都关闭，再结束；关闭完成后不会由该任务重新加载插件，也不会留下新实例的执行组件。
- 当前实例已停止或未初始化，且没有正在处理的重载请求时，命令提示在 AstrBot 插件页重载，不重新启动旧实例。
- 前置检查发现框架重载接口或本插件注册状态不兼容时，命令在停止实例前固定拒绝；停止、解绑或加载过程中失败时，返回固定的未完成提示。两种情况都要求在 AstrBot 插件页检查并重载，不会回退到插件管理器提供的其他重载方法。

实现按 AstrBot v4.29.4 的插件管理接口（公共 `Context` 查询加受控私有生命周期接口）：通过公共 `Context.get_all_stars()` 找到唯一激活的当前插件元数据，终止、解绑和加载在 `context._star_manager._pm_lock` 内执行，依次调用 `_terminate_plugin`、`_unbind_plugin` 和 `load(specified_module_path=...)`。替换实例的公开清理直接关闭精确对象，不获取该锁，也不修改注册表或重新加载。终止前后都复查目标未变化，终止后要求旧实例完全静默，加载后复查新实例接管。方法签名和注册结构见 [star_manager.py](https://github.com/AstrBotDevs/AstrBot/blob/v4.29.4/astrbot/core/star/star_manager.py) 与 [context.py](https://github.com/AstrBotDevs/AstrBot/blob/v4.29.4/astrbot/core/star/context.py)。不使用 `manager.reload` 或其他不检查当前实例身份的入口作为回退。

## 任务字段

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `task_id` | string | 小写字母开头，后续只能是小写字母、数字或下划线，总长 1 到 64；同一目录内不可重复 |
| `name` | string | 非空任务名称 |
| `enabled` | bool | 配置启用状态，默认 `false`；手动签到和自动计划都要求全局和任务都启用 |
| `runtime` | string | `python` 或 `node` |
| `script_url` | string | 固定提交的 HTTPS GitHub 脚本地址，规则见下文 |
| `source_commit` | string | 40 位十六进制提交；必须与 `script_url` 中的提交一致 |
| `sha256` | string | 64 位十六进制预期内容摘要；天翼准备要求与仓库固定值一致，通用任务准备要求下载源码的实际摘要与它一致 |
| `cron` | string | 五段 Cron 表达式，用于预览和自动计划，规则见下文 |
| `user_fields` | array 或 JSON 文本 | 用户字段元数据数组；WebUI 中使用 JSON 文本编辑器 |
| `fixed_env` | object | 固定的非秘密环境变量，名称到字符串值的映射 |
| `input_adapter` | string | `direct_env`、`tianyi_account` 或 `mobile_single_account` |
| `result_adapter` | string | `json_protocol`、`process_only`、`tianyi` 或 `mobile_unverified` |
| `dependency_bundle` | string | `direct_env` 必须为 `none` 或 zip-v1 声明；天翼和移动声明必须为空。插件只在准备时校验并打包，不在宿主机安装依赖 |
| `timeout_seconds` | int | `0` 继承全局值；其他值允许 1 到 240 |
| `experimental` | bool | 实验任务标记，默认 `false` |

`user_fields` 只描述字段要求。实际值只在 `/签到 录入` 过程中接收，认证加密后保存；任务配置中不要填写字段值。`secret` 目前用于字段声明和展示，所有录入字段值都会加密保存。

### 用户字段

`user_fields` 的每一项包含以下键：

| 键 | 类型 | 规则 |
| --- | --- | --- |
| `field_id` | string | 与 `task_id` 相同的标识符规则；同一任务内不可重复 |
| `label` | string | 非空的显示名称 |
| `env_name` | string | 合法 ASCII 环境变量名，保留声明的大小写 |
| `value_type` | string | `string`、`int` 或 `bool` |
| `required` | bool | 是否必填 |
| `secret` | bool | 是否标记为秘密字段 |
| `hint` | string | 可省略的提示文本 |

环境变量名必须匹配 `[A-Za-z_][A-Za-z0-9_]*`。用户字段之间不能有仅大小写不同的重名，用户字段和 `fixed_env` 之间也不能重叠，比较时不区分大小写。以下名称不可使用：

```text
PATH HOME SHELL ENV BASH_ENV IFS
PYTHON* NODE_* LD_* DYLD_*
```

`fixed_env` 的键同样按上面的环境变量名规则校验，值必须是字符串，保留声明的大小写。用户字段和 `fixed_env` 之间不能有仅大小写不同的同名变量，任一重复都会使任务配置无效。

变量按声明的大小写注入。`string` 按原文传递；`int` 以十进制文本传递；`bool` 输入时接受不区分大小写的 `true` 或 `false`，执行时统一传递小写 `true` 或 `false`。

环境变量在配置校验和每次执行时都受数量与大小限制：

- `user_fields` 数量与 `fixed_env` 键数量合计不超过 64。
- 变量名（ASCII）和单个值（UTF-8）各不超过 16 KiB；值中的 NUL 会被拒绝。
- `fixed_env` 的值合计不超过 64 KiB。
- 静态校验还要求 `fixed_env` 值合计加上所有必填字段的最小序列化值（字符串和整数按 1 字节，布尔按 4 字节）不超过 64 KiB。
- 录入保存时，按类型序列化后的实际用户值与 `fixed_env` 值合计不超过 64 KiB；单个用户值同样不超过 16 KiB。

合计只计算变量值，不计算变量名。

`user_fields` 既可以直接传数组，也可以传 UTF-8 JSON 文本。JSON 文本上限为 64 KiB，嵌套深度最多 32 层，不接受 `NaN` 等非标准 JSON 常量。一个任务最多 32 个用户字段。

下面是从天翼模板摘出的字段声明，只描述元数据，不是凭据值：

```json
[
  {
    "field_id": "username",
    "label": "用户名",
    "env_name": "TY_USERNAME",
    "value_type": "string",
    "required": true,
    "secret": true,
    "hint": "天翼云盘登录用户名"
  }
]
```

## 脚本来源

`script_url` 只接受两种形式：

```text
https://github.com/<owner>/<repo>/blob/<commit>/<path>
https://raw.githubusercontent.com/<owner>/<repo>/<commit>/<path>
```

GitHub 页面地址会规范化为 `raw.githubusercontent.com` 形式。URL 必须使用 HTTPS，提交必须是 40 位十六进制，并且与 `source_commit` 相同。以下内容会被拒绝：

- URL 中的用户名、密码、查询参数或片段；
- 非标准端口，443 可以省略或显式写出；
- 空路径段、`.`、`..`、反斜杠和经过过度百分号编码的路径；
- `github.com` 上不是 `blob` 的地址，或缺少脚本路径的地址。

脚本地址只做静态校验。天翼准备不按该地址下载脚本，使用仓库内的 `third_party/tianyi/index.py`，任务中的 `sha256` 只作声明校验，不能证明远端内容已经核对。通用任务准备会从规范化后的地址下载源码，并要求内容摘要等于任务声明的 `sha256`。

## Cron

Cron 表达式固定为五段：分钟、小时、日、月、星期。支持：

- `*` 和数字；
- 月份和星期的英文简称，例如 `JAN`、`MON`；
- 逗号列表，例如 `1,15`；
- 正向范围，例如 `1-5`；
- 步长，例如 `*/10` 或 `1-30/5`。

星期允许 0 到 7，0 和 7 都表示周日；月份允许 1 到 12。日和星期同时受限时按 OR 计算，所以 `0 9 31 2 MON` 仍然有效，因为二月的周一满足星期条件。`@daily`、秒字段、年字段、随机 `H`/`R` 以及 `L`、`W`、`#` 扩展不支持。

插件要求表达式能产生至少三次未来运行时间。无法产生未来日期的表达式会被拒绝。预览时间按 `timezone` 计算并带 UTC 偏移。

全局和任务都启用后，Cron 同时用于自动签到。调度器按秒检查当前到期分钟，只接受落在当前分钟的计划；已经错过的旧计划不补跑，也不排空积压。启动、重载、重新打开全局开关或任务配置版本变化后，只登记之后的计划时间，停机期间和已经过去的计划不会补跑。计划时间按 `timezone` 计算，持久化去重使用 UTC；同一任务同一计划只执行一次，时钟回拨不会重放。

自动计划与手动签到共用串行队列，具体准入、重叠跳过、通知和启用顺序见[自动签到](#自动签到)。关闭全局 `enabled` 或任务 `enabled` 会停止后续自动计划；重新打开后从新的未来计划开始。

## 适配器组合

| 输入适配器 | 运行时 | 结果适配器 | 额外要求 |
| --- | --- | --- | --- |
| `direct_env` | `python` 或 `node` | `json_protocol` 或 `process_only` | `dependency_bundle` 必须为 `none` 或 zip-v1 声明 |
| `tianyi_account` | `python` | `tianyi` | 必须有 `username`、`password` 字段，类型为 `string`，且 `required=true`、`secret=true` |
| `mobile_single_account` | `node` | `mobile_unverified` | 必须有 `authorization`、`phone`、`auth_token` 字段，类型为 `string`，且 `required=true`、`secret=true` |

`tianyi` 结果适配器只能与 `tianyi_account` 搭配，`mobile_unverified` 只能与 `mobile_single_account` 搭配。`direct_env` 任务按 `runtime` 执行 Python 或 Node；子进程只获得固定的 `PATH`、`HOME`、`LANG` 和本次声明的环境变量，凭据文件在启动前移除，不作为命令行参数传入。

通用任务的结果按保守规则记录：

- `json_protocol` 只读取子进程 stdout 中一个完整 JSON 对象的 `status`，且只接受已知业务状态。其他字段、自由文本、stderr 和多余输出都不会成为业务结果。
- `process_only` 不解析业务结果，业务状态记为 `unknown`，进程退出码单独记录。
- 输出超过 64 KiB、超时、启动失败或没有有效结果时，按 `unknown`、`timeout` 或 `config_error` 等状态记录，不推测业务是否已经发生。

以下任一条件成立时，任务必须保持 `enabled=false` 且 `experimental=true`：

- `task_id` 为 `mobile_cloud_experimental`；
- `input_adapter` 为 `mobile_single_account`；
- `result_adapter` 为 `mobile_unverified`。

否则配置校验失败。

## 配置版本

任务详情中的“配置版本”是规范化任务内容的 SHA256 指纹。版本包含时区和任务字段，`__template_key`、对象键顺序以及等价的 JSON 表示不影响版本。修改任务配置会使正在进行的录入失效，已排队或运行中的签到（手动或自动）也会取消尚未发送的业务请求；已保存的凭据不会因此自动替换。自动计划从新版本之后的计划时间重新登记。

名称、字段顺序、字段元数据、脚本声明、时区或有效超时等业务配置变化会改变版本，任务 `enabled` 变化也会改变版本。版本用于识别任务配置是否变化，不是脚本内容摘要；脚本摘要单独由 `sha256` 声明。准备记录按版本和打包输入指纹校验，版本变化后需要重新准备。
